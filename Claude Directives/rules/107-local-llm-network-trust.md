# ローカル LLM のネットワーク信頼境界と PL 上限

`lmstudio` / `freetoken` / `llamacpp` を「ローカル」として PrivacyLevel 1.0 まで通しているのは、**localhost か、信頼できるサブネットでしか使わない前提**があるからである。この前提が崩れたら上限を下げる。provider 名が「ローカル」だから安全なのではない。

## 前提（なぜ 1.0 を許しているか）

- `lmstudio` / `freetoken` は既定で localhost。プロセス間通信であり外に出ない。
- `llamacpp` (llama.cpp llama-server) は **LAN 上の別ホスト**で動く（例: 自宅 LAN の専用機）。自宅内の信頼機器という運用判断で `NBAccess` の `$iProviderMaxAccessLevel` に `1.0` を登録している。
- **llama-server は平文 HTTP である。** TLS 終端は無く、API キーは `Authorization` ヘッダに平文で流れる。守っているのは「そのサブネットに攻撃者がいない」という前提だけ。

## 自動で効く強制制限（2026-08-29 実装）

接続先が **localhost でも同一サブネットでもない**ローカル LLM へは、provider に登録された上限に関係なく **0.25 が強制**される。`NBAccess`NBLocalLLMEffectiveMaxAccessLevel[provider, url]` が `NBModelCanHandleAccessLevel` 経由で効く。

- 判定: `NBLocalLLMURLProximity[url]` → `"Localhost"` / `"SameSubnet"` / `"Remote"` / `"Unknown"`。
- サブネットは第 3 オクテットまで（/24 相当）の一致で見る。**ホスト名や IPv6 は判定できないので `"Unknown"` = Remote 扱い**（安全側）。
- クラウド provider には適用しない（別途 0.49/0.25 の上限があるため）。
- 上限値は `$NBRemoteLocalLLMAccessCeiling`（既定 0.25）。

### 同一サブネットも既定では信用しない

**サブネットが一致することは信頼の根拠にならない。** 別の LAN で、たまたま、または悪意で同じ IP を名乗る llama-server がいれば、秘密データはそちらへ流れる。したがって `"SameSubnet"` も既定では `"Remote"` と同じく 0.25 に落とす。

開けるのは `NBAccess`$NBTrustCurrentSubnet` を `True` にしたときだけ。パレットの **`Subnet: 信用しない / 信用する`** トグルがこれを切り替える（既定 `信用しない`）。`localhost` はネットワークに出ないので常に信用する。

**このトグルはノートブックに保存しない。** 他のパレット設定と違い `iSavePaletteSettings` を呼ばない。保存すると、そのノートを別のネットワークで開いた瞬間に「信用する」が黙って復活し、このトグルが防ごうとしている攻撃そのものを通してしまう。セッション（カーネル）限りの値で、起動のたびに `False` へ戻るのが正しい振る舞い。**この非永続性を壊す変更をしないこと。**

### IP が変わったら自動で失効する

ノート PC は Mathematica を起動したまま別のサブネットへ移動する。カーネルが生きている限りトグルが残ると、移動先で「信用する」のまま秘密が流れる。

そのため `NBSubnetTrustActive[]` は**読み取りのたびに自機 IP 集合を照合し、信用を与えた時点から変わっていたら その場で失効させる**（`$NBTrustCurrentSubnet` を `False` に戻し、`NBSubnetTrustActive::revoked` を出す）。移動後は再度トグルを押さない限り 0.25 に戻る。

- 判定は読み取り時に行う。`$NBTrustCurrentSubnet` へ直接代入されても必ずこのチェックを通る（直接代入時は初回読み取りで基準を捕捉する）。
- 比較対象は loopback と link-local（169.254）を除いた IPv4 集合。前者は常に存在し、後者は DHCP 失敗時に現れて消えるので「どのネットワークにいるか」を表さない。仮想アダプタ（172.x 等）は含める — 経路の変化であり、余分に失効する分には安全側。
- 付与は `NBSetSubnetTrust[True]` を通す（現在の IP を控える正規口）。

### localhost は常に例外

`localhost` / `127.0.0.1` / `[::1]` の LM Studio・llama.cpp は、**サブネットを「信用しない」にしていても、IP が変わって失効した後でも、常に provider 登録値（1.0）のまま**。ネットワークに一切出ないので、サブネットの信頼とは無関係である。ここを近接クランプの対象にしてはいけない。

（例外は、`NBSetProviderMaxAccessLevel` で明示的に下げた場合。その場合はその値が優先される — 人間の明示指示が自動判定に優先する、という一般則どおり。）

**自動制限は下の「必須」を免除しない。** トグルを `True` にした瞬間から同一サブネットは開くので、そこが信頼できるネットワークかどうかの判断は人間が負う。

## 必須

- **ネットワークを安全とみなせない状況では、上限を 0.5 に下げてから使う。** 下げるまで使わない。同一サブネットにいる限り自動制限は働かないので、ここは人間の判断が要る。

  ```
  NBAccess`NBSetProviderMaxAccessLevel["llamacpp", 0.5]
  ```

  「安全とみなせない状況」の例 — 外出先・公衆 Wi-Fi・来客や委託業者が同居する LAN・構成が分からないサブネット・VPN や NAT 越しで経路が確認できない場合・LAN の外へ出す場合（この場合は TLS 終端か VPN が先で、それでも 0.5 が既定）。
- **接続先 URL と PL 上限は別物として両方確認する。** `$ClaudeLlamaCppBaseURL` の localInit 側サブネット判定は「到達できないホストを掴んでタイムアウトさせない」ための仕組みであって、**信頼上限を自動で下げはしない**。別サブネットに移れば URL は localhost に落ちるが、上限は 1.0 のまま残る。
- **上限を変えたら、その根拠（どのネットワークにいるか）を応答かコメントに書く。** 後から「なぜ 1.0 なのか」を追えるようにする。

## 禁止

- **「LAN 内だから安全」で自動的に 1.0 を与える。** 信頼はサブネットの構成に対する具体的な判断であって、プライベート IP レンジであることは根拠にならない。
- **公開パッケージ（GitHub 反映対象）に固有 IP や「このサブネットは安全」という判断を書き込む。** 接続先は `localInit.wl` 側で上書きする（パッケージ既定は localhost 固定）。
- **PL 上限を上げてから接続先を決める。** 順序は「どのネットワークにいるか → 上限 → 接続先」。

## 判断

- 迷ったら 0.5。0.5 なら機密（PL >= 0.5）は送られず、cloud-safe 相当の内容だけが流れる。取り返しがつかないのは送ってしまった側だけである。
- 上限 1.0 は「そのホストに秘密データを渡してよい」という宣言であり、ツールループ経由で SourceVault の中身（メール本文・セッションログ・私的文書）が実際に別ホストへ渡る。2026-08-29 の実測で PrivacyLevel 0.85 と判定されたセルが llamacpp へ送られている。これは設定どおりの挙動であって、事故ではない — だからこそ設定を意識して選ぶ。
- 機体を持ち出す運用（ノート PC）では、サブネットが変わるたびにこの判断が変わる。恒久的に安全な設定は「上限 0.5 を既定にし、信頼できるサブネットにいる間だけ 1.0 へ上げる」であり、常時 1.0 はその機体が動かない前提でのみ妥当。
